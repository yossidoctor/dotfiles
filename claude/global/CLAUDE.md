# Global CLAUDE.md

Strict and unforgiving behavioral rules for Claude Code, loaded every session. Section/rule names are stable IDs — other docs and skills cite them by name; renaming one means updating its referencers.

**Recurring terms**:
- **Falsifier** — the concrete observable proving a rule was violated: the tripwire, not a restatement. A rule's **carve-out** is what it deliberately doesn't cover — any exception marker (`What it's not:`, `Skip:`, `Carve-out:`, a bare exception clause) counts.
- **SoT** (source of truth) — the one file/command that owns a value; everything else derives from it and carries an inline "derived from / cache of `<SoT>`" tag.

## Making things

*Everything you author or change. A rule naming a surface (`*code*`, `*instructional text*`) is scoped to it; the rest bind everywhere.*

### Is it true

- **Accuracy first.** Verify with Read/Bash before asserting; "don't know" beats a guess. An empty grep means Read the source — a path, type, default, or convention is looked up, never inferred. **A read backs its own span and nothing adjacent to it**: one hop past the span is a guess carrying the confidence of the read that stopped short, so either the claim names the span covering it or the span is extended first. A conclusion — "redundant / unused / safe to assume / the tool is broken" — can be wrong with every fact right: trace callers and invariants before acting on one, and re-run the command before a verdict about the environment. Skip: the specific fact established earlier this session, never the subject it belongs to; language/tool knowledge no repo file owns. Falsifier: an asserted fact that doesn't match source; a claim whose support sits beside what was read rather than inside it; "it's dead / already-validated" acted on with no Read/Grep behind it; a tool declared broken on one failed invocation.
- **A supplied identifier needs a binding site, not a mention.** Before writing an externally-supplied value (address, account id, endpoint, key) anywhere it will be acted on, find the place that would break if it were wrong — a defining config or a consuming service. Carriers — prose quoting it, instructions echoing it, a rendered surface it was read off by eye, data the suspect writer populated — inherited the error rather than confirming it: N copies of one poisoned origin are one source, not N. No binding site → ask, don't write it. Skip: values the task itself mints; one already confirmed this session. Falsifier: a supplied identifier reached a config/fixture/commit or a query filter backed only by carriers; a structure claim resting on a corpus the suspect writer populated.
- **Captured state is a lie waiting to happen.** Don't enumerate what a command can list live — name the command ("run `<tool> list`", not "envs are: foo, bar, baz"). Carve-out: values whose SoT *is* this file — state directly. Falsifier: a doc lists what one command would enumerate, without naming it.
- **A local ref is a cache; the remote is the state.** `origin/main` dates from the last fetch, and two unfetched refs agree by construction. Fetch in the command that reads: `git fetch -q origin && git rev-parse origin/main`. Carve-out: a SHA that *is* the subject (a deployed commit, a merge-base) — named as the commit it is, not a branch's position. Falsifier: a branch tip, "up to date", or ahead/behind count asserted with no fetch that turn.
- **No backward-looking phrasing.** Authored text, names, and fixes state the current invariant with no trace of the past that produced it — no contrast with a prior state, whether by tense or by negating what a removed mechanism did, no incident retold, no lesson-learned aside; the war story goes in the commit/PR. Scope a rule to the defect, not the instance: a clause naming the one shape that just bit is the incident surviving as a carve-out. A hard-won gotcha stays, restated as a standing property of the thing ("BSD `sed -i` requires an explicit suffix argument") — the test is whether the sentence would still be written had the removed or changed mechanism never existed; one that only reads against it is the history, whatever its tense. Skip: upstream deprecations, structural labels, variable names (`previous_status`). Falsifier: a sentence whose content is the prior state — a contrast with it, its mechanism negated, its name carried forward — outside the skip list; a clause that would need rewriting for the next case failing the same way.

### Does it live in one place

- **Strict single SoT.** Every literal lives in one file; mirrors carry a derived-from tag, and a tagged mirror *satisfies* this rule — check the tag before reporting a duplicate. Falsifier: the same value in two tracked files with no tag; a tagged mirror reported as duplication.
- **Rules live where they fire.** *Instructional text.* A stage-specific rule sits inline in its stage; only genuine cross-stage invariants stay centralized. Falsifier: a one-stage rule in a shared preamble.

### Is it the minimal shape

- **Delete dead weight, don't reorganize it.** A pass-through, an identity transform, or a guard on a case upstream invariants already exclude — remove it, don't wrap or rename it; inline a single-use helper with no real logic. Skip: genuine mappers and substantial single-use helpers; real work at the wrong level moves upstream (§ A fix lands where the defect is), it doesn't get deleted. Falsifier: such a layer kept, added, wrapped, or renamed instead of removed.
- **A guard on a fallible producer reports; it does not repair.** Folding, capping, or overwriting a bad value in place turns a contract violation into a silent miss — the value looks chosen downstream and the producer is never fixed. Skip: a value whose correction is the function's whole job (a parser, a normalizer); an unparseable value, which fails at parse time instead. Falsifier: a value silently rewritten on a path whose contract forbade it.
- **It reads top-to-bottom as one flow.** *Code.* A linear main function over a chain of trivial shims; extract only real named substance. Skip: don't inline substantial logic into one giant function. Falsifier: the main path can't be followed without hopping trivial forwarding helpers.
- **Names carry domain meaning, not lineage.** Name what a thing *is* in the domain, not its position or origin; rename inherited names that lie. Skip: a truthful inherited name stays — no rename sweeps. Falsifier: a graph-position or origin name (`parent`, `copyOf`, `from_v1`) where a nameable domain term exists; a name asserting behavior the code no longer has.
- **No comments, no docstrings.** Code needing prose to be understood is bad code — fix it (clearer names, smaller functions, obvious flow), don't annotate it; the WHY belongs in the commit/PR. No context earns an exception: a comment is an unenforced contract that rots silently — name the thing so the agreement is legible and put the rest in the commit. A diff into a comment-dense file thins it. Skip: machine-required text stays, because tooling breaks without it; a script's header block in a config repo (`~/dotfiles` or a layer repo installed on top of it) is that repo's README-declared SoT for the script's behavior and rationale, so it is maintained, not thinned — the body below it holds to this rule; the bar is self-evident code, never confusing code. Falsifier: a diff keeps a comment a name or structure could carry; a comment surviving because of what surrounds it; a diff leaving more comments than it found; a header asserting behavior the script no longer has.
- **A script on a hot path spends nothing before it knows it has work.** *Scripts, hooks, runners — anything invoked per tool call or per loop iteration.* Order the cheapest discriminating test first: a shell `case` on the raw input, then the derived forms, then the interpreter. Stripping and flattening only ever REMOVE characters, so a literal absent from raw text cannot appear in a derived form — that is what makes the early gate sound, and a gate whose literal set omits one trigger silently disables that rule. `jq` starts in ~2.5ms against `python3`'s ~20ms, so JSON in and out is `jq`; a `python3` block earns its place only by doing real parsing work the shell cannot. Never hand-extract a JSON string with parameter expansion: it truncates at the first escaped quote, so a gate reading a command field fails OPEN. Skip: a one-shot script, where clarity wins outright. Falsifier: an interpreter spawned on a path that exits without acting; a derived form built before the gate that would have skipped it; a trigger literal in a pattern but missing from the gate; a JSON field read by `${var#...}` where a wrong answer gates anything.
- **A timing claim comes from `hyperfine`, not a loop around the thing.** A shell loop bracketed by clock reads measures cold caches, the clock reads themselves, and one scheduling accident — at the millisecond scale that noise is larger than the effect, so it reports speedups that are not there and hides ones that are. `hyperfine --warmup <n> -N '<cmd>'` warms first, repeats, and prints the deviation that says whether the difference survives it; `-N` drops the intermediate shell, and a command it measures under ~5ms it flags as unresolvable. A number without a deviation beside it is an anecdote. Skip: a whole-run wall time in seconds, where the effect dwarfs the noise. Falsifier: a before/after speedup asserted from a single run or a `date`-bracketed loop; a per-invocation cost in milliseconds with no run count or deviation behind it.
- **Every behavioral rule carries three roles, compressed without loss.** What to do, the carve-out, the falsifier — a ceiling, not a quota: a role with nothing real behind it is omitted, never invented. Trimming cuts filler — never a gotcha, edge case, or falsifier, and never softens a MUST to a hedge; a file merely too long pushes branch-only content down a rung (inline → reference → external file), it doesn't delete. Added text earns its place sentence by sentence: a why-clause stays only when it names a consequence the reader cannot derive and would act on. Cite a source or state the content, never both. Skip: simple facts, one-line tool preferences. Falsifier: a rule over two sentences missing a role; a carve-out or why-clause with no real exception behind it, sized to the surrounding rules; a trim that dropped a falsifier/carve-out or softened a MUST; length cut by deletion where relocation kept it reachable; an added sentence changing no behavior; a paraphrase beside its citation.

### How the edit lands

- **A fix lands where the defect is, as a rewrite — never as a layer beside it.** Restate the rule, function, or check that should have prevented the case — whole, so it covers the case by construction and reads as though it always did. A second paragraph restating the first, one more `OR` on a falsifier, or a clause narrating the triggering case is the same defect *inside* the right target; the test is the cold reader: nothing reveals which clause came last. Nothing upstream can absorb it → that absence is the finding — write the missing rule/validator/type where it fires. Skip: new scope with no owner; a real enumeration gaining a row; an adapter at a boundary you don't control; § Surgical updates still binds. Falsifier: a fix added a bullet/branch/guard/wrapper while the owning rule went untouched; the same guidance now in two places.
- **Surgical updates.** *Edit mechanics.* Touch only what the change requires: `Edit` with the minimum unique `old_string`, preserving the surrounding structure and idiom. Skip: a refactor the user asked for; a rewrite § A fix lands where the defect is demands. Falsifier: a `Write` where targeted `Edit`s would land; an edit restating untouched lines; this rule cited to license what another bans.
- **A tool that caused the trap is the defect — stop, and fix the tool.** *Skills, hooks, docs, runners.* When an error or wasted back-and-forth traces to a tool (missing warning, misleading guidance), `Edit` it in the same session — reaching for a second approach *because* a tool misled you is the signal. Placement: § A fix lands where the defect is; wording: § No backward-looking phrasing. Skip: your own misuse (re-read, don't edit); a stale test encoding old behavior (fix the test); genuinely new scope. Falsifier: hit a tool trap and routed around it without editing the tool that session.

## Explaining things

*Any reply, report, review comment, or doc that describes how parts relate — a flow, a call chain, a fork, a sequence, a lifecycle, a state machine, a dependency or ownership map, a current-vs-target comparison.*

- **Draw it before you say it.** It opens with a fenced diagram, unasked, and the prose after it carries only what no box holds: the verdict, the anomaly, the ask, the why. Form by the arrow of time — a sequence diagram (lifelines, solid out, dashed back) where order and returns matter; a box-and-arrow map where relations hold regardless of order; a gutter-labelled fork for a branch; a hops × variants table for a comparison. The diagram is titled with the question it answers; edges say what changes across them (`PENDING → FAILED`, `address → geocoded_address`), never a bare verb; a legend for any line style beyond a plain arrow. `file:line` and per-hop values sit in a table beside the figure, not in boxes. It fits 80 columns and one screen, split by concern past that; plain ASCII where the text may reach a commit or diff. Skip: a single hop; a value lookup; a diff already legible as code. Falsifier: relations, order, or a comparison explained in prose or numbered steps with no fenced diagram in the same reply; a diagram produced only once asked for; an edge labelled with a bare verb; a mechanism with returns drawn as a one-way chain; a line past 80 columns.

## Workspace mechanics

*Standing facts and constraints other rules and skills reference.*

- **A working tree holds other sessions' uncommitted work; touch only the paths you edited.** Several sessions run against the project trees and `~/dotfiles` at once, so any command whose scope is the tree or the index — `git stash`, `git restore`, `git checkout --`, `git clean`, `git reset` — reaches files a concurrent session is mid-edit on, and the work it discards was never committed and cannot be recovered. Name the paths: `git add <path>`, `git restore <path>` for a file you yourself changed this session, and `git status --porcelain <path>` to see it. Bare `git add -A`/`-u` is the same defect — it stages whatever else is dirty. To read a committed version, `git show HEAD:<path>` writes to stdout and touches nothing; that is the way to diff or benchmark against HEAD, never a stash round-trip. Skip: a repo the session created itself (a sandbox worktree, a scratch clone). Falsifier: a stash/restore/checkout/clean/reset with no path operand; a staged path this session did not edit; a comparison against HEAD performed by stashing.

- **A subagent starts in the session's project directory, with the same CLAUDE.mds loaded.** The dispatch prompt is the only channel — the parent's conversation doesn't cross — so paths, decisions, and error text go in the prompt string, and a reviewer of the parent's work is isolated by construction. There is no per-dispatch cwd parameter. Re-derive: dispatch a throwaway agent that runs `pwd` and reports whether a project CLAUDE.md heading is in its context.

- **Git identities route by tree; the Claude account is a third thing.** Identity SoT: `~/dotfiles/README.md` § Git identity & credentials — `git/config` includes `git/identity` for `~/dotfiles/`, a project layer includes its own tree's email through `~/.config/git/local.gitconfig`, and `useConfigOnly = true` fails a commit outside every included scope rather than guessing; gh routing is the identity files in `~/.config/git/identities.d/`. A tree's email is `git config -f <that scope's config file> user.email`, and a project's `CLAUDE.md` names which of its systems that email keys. `# userEmail` is only the active Claude account (claude-swap-rotated) and substitutes for no git identity. Skip: `# userEmail` where the Claude account itself is the subject (attribution, account swaps). Falsifier: `# userEmail`'s value used as a git identity or as the key to a project's credential store; a scope's email asserted without a `git config -f` read behind it.

- **Read, Edit, and Write take the physical path inside the repository, never a symlink into it.** The file tracker keys whatever path a call names, so a Read through a link and an Edit on its target desync. `~/.claude/*` and a project's `.claude/*`, `CLAUDE.md`, `docs`, and `scripts` are dotbot links into a config repo — `readlink -f <file>` resolves one, and the deploying repo's `install.conf.yaml` is the link list. Prose, citations, and `Bash` keep the deployed name (`~/.claude/...`, the project path), which is what docs and scripts are written against. Skip: symlinked dirs whose target is not a repository (`/tmp` → `/private/tmp`) — used consistently they never desync. Falsifier: a Read/Edit/Write `file_path` that resolves into a repository by a route other than that repository's own path.

- **Reading a file is `Read`, not `cat` or `sed -n` in a shell.** It takes offset/limit natively, and only a path the tracker saw can be edited — a shell read reaches the same bytes while leaving the follow-up `Edit` with nothing to key on. Skip: a read feeding a pipe or redirect, a heredoc, multi-file concatenation, `sed -i`, and throwaway paths (`/tmp`, a scratchpad, task output), where the bytes go somewhere other than the transcript. Falsifier: a `cat <file>` or `sed -n '<a>,<b>p' <file>` whose operand is a source file.

- **A command names its own directory instead of riding a `cd`.** `git -C`, `poetry -C`, `make -C`, `npm --prefix`, and a path operand for `rg` all take one; `gh` takes `-R <owner/repo>`. A `cd` that fails leaves the chained command running in the previous directory. Skip: a command with no directory flag to name (`for`, `python3`, `./script.sh`), a multi-directory sweep, a subshell `( cd … )`, and a flag that failed on a path it built from the one you passed — there the cwd form is what works. Falsifier: a `cd <dir> && <cmd>` where `<cmd>` has a directory flag.

- **The config repos — `~/dotfiles` (the public base) and the private layer repo installed on top of it (`readlink -f ~/.config/git/local.gitconfig` names its tree) — are solo repos: commit straight to `master`.** No branch, no PR; a reviewer does not exist, so "branch first on the default branch" does not apply there. Each README owns its layout and mechanics, and its `install.conf.yaml` is the manifest: a tracked file it does not declare is not deployed, a new hook or script needs its own `link:` line, and `./install` re-runs are the only deploy step. Falsifier: a branch, PR, or non-`master` push in either repo; a new tracked file with no manifest line behind it.

- **Hooks and install steps run under macOS `/bin/bash` 3.2, live through symlinks, and are table-tested.** `#!/usr/bin/env bash` (Homebrew bash when on PATH, `#!/bin/sh` only where POSIX is meant), no bash-4+ syntax (`${var,,}`, `declare -A`, `printf '%(…)T'`, `mapfile`) without a `BASH_VERSINFO` gate. A manifest `shell:` step re-runs on every `./install` under `set -e`, so it no-ops when its state already holds and carries `|| true` when it needs sudo or a TTY. The deployed hook paths are links into the repo, so an edit runs on the very next tool call in the editing session and a broken edit bricks that tool at once; `settings.json` registrations snapshot at session start. Every regex-gating hook has a `cases-<hook>.txt` under its `tests/`, run by that dir's `run-tests.sh` after any pattern change (the case-file glob is the coverage list); case files hold the banned patterns as text, so they are written with `Write`/`Edit` — a `Bash` heredoc is denied by the hook itself. Skip: a script that never runs under a hook or `./install` may use bash 4+; banner and nudge hooks with no allow/deny logic need no case file. Falsifier: a bash-4 construct in a hook or install step with no version gate; a `shell:` step that repeats a visible side effect on a second `./install` or can abort it on a prompt; a regex change with no case added and the runner not run.

- **CLAUDE.md files in scope:**
  - `~/dotfiles/claude/global/CLAUDE.md` (this file) — global, every project; deployed as `~/.claude/CLAUDE.md`.
  - A project's own `CLAUDE.md` — loads only when that directory is the session root. When a layer repo deploys it, that repo's README owns the link list (`install.conf.yaml`) and says which of the project's files are per-file links (a new one needs its own entry) and which ride a dir link.
